# Adding A City Pack

Fitinerary city packs live under `backend/app/data/cities/<city_id>/`. Each pack is sample-labelled unless you have verified sources and tests proving otherwise.

## 1. Create The Folder

Add:

- `city.json`
- `attractions.json`
- `hotels.json`
- `travel_times.json` generated by script

Use a lowercase, URL-safe `city_id` such as `singapore`.

## 2. Fill `city.json`

Include the display name, country, local currency, labelled sample FX rate, coordinate bounding box, transit model constants, default day window, default value of time, closing-day note and provenance statement.

The FX rate is for display only. The optimiser keeps all costs in the city's local integer currency units.

## 3. Add Attractions

Use 10-15 records for a demo-sized pack. Every record needs:

- coordinates inside the city bounding box
- seven-day opening hours, `null` for closed days, or `"unknown"`
- admission cost, or `null` for unknown price
- indoor/outdoor flag
- advance-booking flag
- aliases for name matching
- sample provenance for record, hours and cost

Descriptions are untrusted text. They must never enter prompts.

## 4. Add Fictional Hotels

Use 3 fictional hotels with invented names and rates. Include real neighbourhood names only as approximate areas.

Make at least one hotel cheaper and farther away so the hotel-comparison story can show a real trade-off without claiming real market data.

## 5. Generate The Matrix

Run:

```bash
cd backend
python scripts/build_travel_matrix.py --city <city_id>
```

Do not hand-edit `travel_times.json`. It must be complete, symmetric, zero on the diagonal and labelled `estimated`.

## 6. Test And Evaluate Separately

Run:

```bash
cd backend
.venv/bin/pytest tests/test_city_packs.py
.venv/bin/python scripts/run_city_evaluation.py --trips 20
```

Tokyo remains the full headline evaluation. Added cities use smaller, separate sample reports and must not be pooled into one claim.
